# 💻 Python en el ordenador del aula (Sprints 4 y 16)

Casi todo el curso se hace en **Colab**, en el navegador. Hay **dos momentos** que no: el **reto del Sprint 4** (`kpis.py` y sus pruebas, que se ejecutan en la terminal del ordenador del aula) y el **demostrador** del Sprint 16 (paso 4 y paso 6), que usa Streamlit, y Streamlit **no se abre en Colab**. Esta guía te lleva de cero a «escribo una orden y funciona», en cinco minutos. No hace falta instalar nada en casa: el aula ya tiene **Anaconda + Visual Studio Code**.

## 1. Qué es una terminal

Una ventana donde se escriben órdenes. Cada línea que escribes y pulsas **Intro** es una orden. Puedes **copiar y pegar** las del paso; no hace falta aprender más.

## 2. Abrirla (en Visual Studio Code)

1. Abre **Visual Studio Code**.
2. **Archivo → Abrir carpeta…** y elige la carpeta del proyecto: en el Sprint 4, la del reto (la que tiene `kpis.py`); en el Sprint 16, `demostrador` (la que tiene `app.py`).
3. **Terminal → Nuevo terminal**. Abajo aparece la ventana, ya dentro de esa carpeta.

## 3. Comprobar que todo está

Escribe estas dos órdenes, una por línea:

```text
python --version
pip --version
```

Tienen que salir dos líneas con números (por ejemplo `Python 3.13.x` y `pip 25.x`). Después escribe `dir` (Windows) o `ls` (Mac y Linux): tienen que salir los ficheros del proyecto (`kpis.py` y `test_kpis.py` en el Sprint 4; `app.py`, `logica.py`, `modelo` y `tests` en el Sprint 16). Si no salen, estás en otra carpeta: ciérrala y repite el apartado 2 eligiendo la carpeta correcta.

## 4. Las cinco órdenes que usarás

| Orden | Para qué sirve |
|---|---|
| `python -m venv .venv` | Crea un entorno limpio (una caja vacía para las librerías de este proyecto). |
| `.venv\Scripts\activate` (Windows) o `source .venv/bin/activate` (Mac y Linux) | Entra en esa caja. Si funciona, la línea empieza por `(.venv)`. |
| `pip install -r requirements.txt` | Instala las librerías de la lista. Tarda unos minutos. |
| `pytest -q` | Pasa las pruebas del demostrador. |
| `streamlit run app.py` | Abre la app en el navegador (`http://localhost:8501`). Para pararla: **Ctrl + C** en la terminal. |

## 5. Si algo falla

| Veis… | Qué significa | Qué hacer |
|---|---|---|
| `python` no se reconoce como comando | El terminal no es el de Anaconda. | Abrid **Anaconda Prompt** desde el menú de inicio, escribid `cd` seguido de un espacio, arrastrad la carpeta del proyecto a la ventana y pulsad Intro. Repetid el apartado 3. |
| En Windows: `la ejecución de scripts está deshabilitada en este sistema` al activar `.venv` | PowerShell bloquea el script. | En el terminal de VS Code, pulsad la flecha junto al **+** y elegid **Command Prompt** (no PowerShell); abrid uno nuevo y repetid la activación. |
| `pip install` se queda mucho rato o da error de red | La red del aula va lenta o bloquea algo. | Esperad 5 minutos; si sigue, avisad al docente. La alternativa es el cuaderno con *widgets* `S16_01`, que no necesita instalar nada. |
| `streamlit` no se reconoce | El entorno no está activado o `pip install` no terminó. | Activad `.venv` (la línea debe empezar por `(.venv)`) y repetid `pip install -r requirements.txt`. |
| La app no abre o dice que el puerto está ocupado | Ya hay una app abierta en otra terminal. | Cerrad esa terminal (icono de la papelera) o pulsad **Ctrl + C** en ella y repetid. |
| Aparece una carpeta `.venv` enorme al subir a GitHub | Se ha incluido el entorno. | **No se sube nunca** `.venv/`: pesa cientos de megas. Subid solo los archivos del paso. |
